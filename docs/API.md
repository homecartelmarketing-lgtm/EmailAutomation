# HTTP API Reference

All routes are registered in `src/server.js` via four route modules. There is **no authentication layer** on
any route — the service is intended to sit behind a private network/proxy. See
[OPERATIONS.md](OPERATIONS.md#security-posture) before exposing `/api/admin/*` publicly.

Base URL is whatever `APP_BASE_URL` resolves to. Bodies are JSON unless noted.

---

## Service & dashboard

| Method | Path | Purpose |
| :--- | :--- | :--- |
| `GET` | `/` | HTML dashboard. Add `?format=json` (or send `Accept: application/json` without `text/html`) for a JSON service descriptor. |
| `GET` | `/ui`, `/admin`, `/dashboard` | Aliases that serve `public/index.html`. |
| `GET` | `/health` | `{ "status": "ok", "store": "<SHOP_DOMAIN>" }` |
| `GET` | `/homecartel-tracker.js` | Storefront tracker script (`public/homecartel-tracker.js`). |
| `GET` | `/images/:file` | Serves `public/images/<basename>`. Traversal-safe via `path.basename`. 1-day cache. |

## Shopify webhooks — `/api/webhooks/shopify/*`

Every route in this group passes through a `preHandler` hook that verifies `X-Shopify-Hmac-Sha256` against
the **raw** request body. Missing or invalid signature ⇒ `401` and no database writes. The last 50 attempts
are kept in `recentWebhookLogs` and surfaced by `/api/admin/overview` and `/api/admin/diagnostics`.

| Method | Path | Shopify topic | Behaviour |
| :--- | :--- | :--- | :--- |
| `POST` | `/checkouts` | `checkouts/create`, `checkouts/update` | Upserts customer + cart (`status='abandoned'`); schedules `abandoned_cart` if the flow is enabled. |
| `POST` | `/carts` | `carts/update` | Same handler as `/checkouts`. |
| `POST` | `/orders` | `orders/create` | Marks cart `recovered`, cancels pending `abandoned_cart` jobs by `checkout_id` and by email; records `order_completed`. |
| `POST` | `/fulfillments` | `fulfillments/create` | Records `fulfillment_created`; schedules `post_purchase` if enabled. |
| `POST` | `/customers` | `customers/create` | Rejects disposable/bot emails; records `customer_created`; enqueues the 3-part welcome drip if enabled. |

Responses are always `200` with a `scheduled` field describing the outcome
(`abandoned_cart`, `welcome_drip`, `post_purchase`, `skipped_flow_disabled`,
`skipped_no_email`, or `cart_cancelled`), except `401` on HMAC failure.

Note: the checkout/cart handler returns `200` and **skips** scheduling when the payload has no email — the
event is logged but nothing is enqueued.

## Storefront tracking — `/api/track/*`

CORS is open (`Access-Control-Allow-Origin: *`) for these paths, and `text/plain` bodies are accepted so
`navigator.sendBeacon` works.

### `POST /api/track/event`

```json
{ "visitorId": "hc_vid_abc123", "eventType": "page_view", "properties": { "url": "/products/x" } }
```

`visitorId` and `eventType` are required (`400` otherwise). The event is persisted and broadcast over SSE.
A `timestamp` is injected into `properties` if absent.

Response: `{ "success": true }`

### `POST /api/track/identify`

```json
{ "visitorId": "hc_vid_abc123", "email": "shopper@example.com", "name": "Maria" }
```

Upserts the customer, then back-fills every prior event from that `visitorId` onto the customer record
(session identity stitching). Disposable/bot/invalid emails are rejected with `400`.

Response: `{ "success": true, "customerId": 12, "email": "...", "reconciledEvents": 37 }`

### `POST /api/track/cart-sync`

```json
{ "visitorId": "hc_vid_abc123", "cartToken": "abc..." }
```

Links an anonymous visitor to a Shopify cart token, so later cart webhooks can be attributed.

Response: `{ "success": true }`

### `GET /api/track/counter`

Public stats endpoint, no auth. Returns store-wide visit counters:

```json
{ "storeVisits": 4210, "uniqueVisitors": 1337, "anonymousVisitors": 900, "activeNow": 4, "asOf": "2026-11-11T00:00:00.000Z" }
```

`activeNow` counts distinct visitors with activity in the last 15 minutes.

## Unsubscribe — `/api/unsubscribe`

`GET /api/unsubscribe?email=<email>&token=<hmac>`

The token is `HMAC-SHA256(secret, lowercased-trimmed email)` in hex, generated by
`generateUnsubscribeToken()`. Verified in constant time. Invalid token ⇒ `403`; missing email ⇒ `400`.

On success the customer is flagged `unsubscribed` (which makes the scheduler cancel their pending jobs) and
an HTML confirmation page is returned.

Emails render this link automatically — the renderer builds it from `APP_BASE_URL` plus a token signed with
`SHOPIFY_WEBHOOK_SECRET`.

## Admin — `/api/admin/*`

Designed for the bundled dashboard. **Unauthenticated.**

### Read

| Method | Path | Purpose |
| :--- | :--- | :--- |
| `GET` | `/overview` | Counts (customers, abandoned/recovered carts, pending jobs, sent emails, total events) plus the last 10–15 customers/carts/jobs/logs and `recentWebhookLogs`. |
| `GET` | `/diagnostics` | Version (git SHA), flow list, masked secret, provider, `appBaseUrl`, `autoDispatchEnabled`, recent webhook attempts. |
| `GET` | `/staged-jobs` | All `pending` jobs with parsed context, customer name, and flow label/number. |
| `GET` | `/jobs/:id/preview` | Renders that job's HTML email inline (`text/html`). `404` if the job is missing. |
| `GET` | `/preview/:template` | Renders any template with sample data. `:template` is a flow key. |
| `GET` | `/events?limit=200` | Recent behavioral events, parsed and normalised. `limit` capped at 1000. |
| `GET` | `/shoppers?limit=300` | Same source as `/events`, shaped for the shoppers view. |
| `GET` | `/events/stream` | **SSE.** Live event feed plus `: ping` every 20 s. |
| `GET` | `/flows` | All flow settings with `is_enabled` (boolean), `pendingCount`, `sentCount`. Welcome counts aggregate the three drip keys. |
| `GET` | `/resend/status` | Resend domain record (verification state). `400` without `RESEND_API_KEY`. |
| `GET` | `/resend/email/:id` | Delivery status for a Resend message id. |

### Write

| Method | Path | Body | Purpose |
| :--- | :--- | :--- | :--- |
| `POST` | `/jobs/:id/send` | — | Sends one staged job now, bypassing the scheduler gates but still honouring unsubscribe. `400` if already sent or unsubscribed. |
| `POST` | `/jobs/:id/cancel` | — | Marks the job `cancelled`. |
| `POST` | `/cancel-all-pending` | — | Cancels **every** pending job. Returns `cancelledJobs` count. |
| `POST` | `/autosend/toggle` | `{ "enabled": bool }` | Flips the in-memory master switch. When disabling, also cancels all pending jobs. Not persisted — a restart resets it to `ENABLE_AUTO_DISPATCH`. |
| `POST` | `/flows/:flowKey/toggle` | `{ "enabled": bool }` | Enable/disable a flow. Disabling cancels that flow's pending jobs. `404` for unknown key. |
| `POST` | `/flows/:flowKey/delay` | `{ "delayHours": number }` | Sets the per-flow delay. `400` if not a non-negative number. |
| `POST` | `/clean-bots` | — | Deletes customers (and their logs/jobs/events) whose email fails disposable/bot validation. Returns `removedCount` and `removed[]`. |
| `POST` | `/resend/verify` | — | Asks Resend to re-verify the sending domain's DNS. |
| `POST` | `/send-test` | see below | Sends one immediate test email. |
| `POST` | `/simulate` | see below | Seeds a scenario for demos/manual dispatch. |

#### `POST /api/admin/send-test`

```json
{
  "to": "you@example.com",
  "template": "abandoned_cart",
  "subject": "Optional override",
  "customerName": "Maria Santos",
  "items": [ { "title": "...", "price": "₱1,000.00", "imageUrl": "...", "url": "..." } ],
  "viewedItems": [ ... ],
  "claimUrl": "https://..."
}
```

`to` is required. The handler substitutes believable HomeCartel product defaults (Talisa, Kevin, Lorvanar,
Anastasia) when `items`/`viewedItems` are omitted, and prefers the recipient's real browsing history for
`viewedItems` when available. Uses whatever `EMAIL_PROVIDER` is configured.

#### `POST /api/admin/simulate`

`{ "scenario": "<name>", "data": { ... } }`. Accepted scenarios:

`abandoned_cart` / `flow_1`, `welcome` / `flow_2`, `browse_abandonment` / `flow_3`, `winback` / `flow_4`,
`post_purchase` / `flow_5`, `order_complete`, `run_scheduler`.

Each flow scenario upserts a demo customer and schedules a job at `now` (immediately due). `order_complete`
cancels pending cart reminders. `run_scheduler` invokes a dispatch cycle with `now` set 30 days ahead so
everything staged becomes due — this is the standard way to flush staged jobs manually.

`400` for an unknown scenario.

> Flows 3 and 4 are only reachable through this endpoint — there is no production trigger. See
> [FLOWS.md](FLOWS.md#flow-3--browse-abandonment).

## Error conventions

| Status | Meaning |
| :--- | :--- |
| `400` | Missing/invalid parameters, already-sent job, unsubscribed recipient, unknown scenario |
| `401` | Shopify HMAC verification failed |
| `403` | Invalid unsubscribe token |
| `404` | Unknown job, unknown flow key, missing asset |
| `500` | Resend API error or render failure |

Errors return `{ "error": "<message>" }` except the webhook 401, which returns
`{ "error": "Unauthorized: Invalid Shopify HMAC signature" }`.
